# NetPractice

Локальный тренажёр для ежедневной практики сетевого администратора. Короткое занятие на 10–15 минут: подсети, диагностика, VLAN, маршрутизация, Linux и комплексные разборы.

Приложение работает на вашем компьютере, не отправляет данные в интернет и не требует регистрации, API-ключей или внешних сервисов. Прогресс хранится в обычном файле SQLite.

---

## Что уже есть

- **Ежедневное занятие** — 8 заданий, подобранных из доступных тем: новые вопросы, повторение ошибок и закрепление старого материала. Незаконченное занятие сохраняется и продолжается с того же места.
- **Семь модулей** — от основ сетей до комплексных лабораторных работ, всего **83 задания**. Следующий модуль открывается после практики предыдущего.
- **Библиотека `.nptpack`** — установка пользовательских курсов из ZIP-пакета, предпросмотр до записи в базу, обновление, удаление с сохранением истории, экспорт и демонстрационный пакет по IPv4.
- **Пять форматов заданий**:
  - короткий ответ (IP, маска, CIDR, число, текст);
  - расчёт по нескольким полям (например, адрес сети + broadcast + число узлов);
  - выбор варианта;
  - технический сценарий с развёрнутым ответом;
  - поиск неисправности.
- **Проверка ответов**:
  - числа, IP-адреса, маски и CIDR проверяются детерминированно;
  - маска принимается и как `255.255.255.192`, и как `/26`;
  - для шлюза принимается любой корректный адрес узла внутри подсети;
  - развёрнутые ответы проверяются по ключевым понятиям: видно, какие пункты учтены, а какие пропущены;
  - если автопроверка не поняла корректную формулировку, ответ можно зачесть вручную (XP при этом начисляется только один раз).
- **Повторение ошибок** — неверные ответы попадают в отдельный список; верный ответ убирает задание из списка.
- **XP и серия дней** — XP за задание начисляется один раз за всё время, бонус +15 XP даётся за завершённое ежедневное занятие один раз в календарный день. Серия считается по дням, когда вы отвечали на задания.
- **Статистика** — серия, максимум, XP, точность, календарь активности за 12 недель, прогресс по модулям, последние ответы.
- **Экспорт и импорт JSON** — резервная копия прогресса, перенос на другой компьютер, режимы «объединить» и «заменить».
- **Тёмный интерфейс на русском** — крупные кнопки, адаптивная вёрстка без горизонтальной прокрутки, отдельная нижняя навигация на телефоне.
- **PWA-каркас** — манифест, иконки и кэш статической оболочки. Устанавливается в Chrome/Edge на компьютере через `localhost`. Подробности и ограничения — ниже.
- **Без внешних ресурсов** — нет CDN, внешних шрифтов, картинок и трекеров. Всё лежит в проекте.

## Быстрый старт

### Windows

1. Установите [Python 3.11+](https://www.python.org/downloads/) (при установке включите **Add Python to PATH**).
2. Дважды щёлкните `run.bat`.

Скрипт сам создаст `.venv`, установит зависимости и запустит сервер. Откройте в браузере:

```
http://127.0.0.1:5000
```

Остановить сервер — `Ctrl+C` в окне консоли.

### Linux / macOS

```bash
chmod +x run.sh
./run.sh
```

Если `chmod` не нужен или файл уже исполняемый:

```bash
./run.sh
```

### Ручной запуск

Windows:

```bat
py -3 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python app.py
```

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Первый запуск требует интернета только для установки Flask и pytest. Дальше приложение работает офлайн.

## Android APK

В каталоге `android/` лежит автономная Android-обёртка на Kotlin + Chaquopy. Она не дублирует бизнес-логику: при старте поднимает существующий Flask-сервер на `127.0.0.1` и открывает его в WebView. SQLite, шаблоны, статика, `.nptpack` и JSON-резервные копии используются те же, что и в desktop-версии.

### Сборка

Нужны JDK 17, Android SDK 35 (platform и build-tools 35), Python 3.15 и Gradle 8.9+. Путь к Python можно указать в `android/app/build.gradle` в `buildPython`.

```bat
cd android
gradlew.bat assembleDebug
```

Linux / macOS:

```bash
cd android
./gradlew assembleDebug
```

Готовый APK:

```text
android/app/build/outputs/apk/debug/app-debug.apk
android/NetPractice-debug.apk
```

Поддерживаются только 64-битные ABI: `arm64-v8a` (телефоны) и `x86_64` (эмулятор). Минимальная версия Android — 7.0 (API 24).

### Установка и данные

```bat
adb install -r android\NetPractice-debug.apk
```

APK работает без компьютера и интернета. Сервер слушает только loopback, WebView не может уйти на внешний сайт. База и секрет хранятся в app-private каталоге `files/netpractice/`; импорт `.nptpack` и JSON, а также экспорт идут через системный файловый диалог (SAF), без доступа ко всей файловой системе.

### Что проверено

- Gradle-сборка `assembleDebug` проходит; APK содержит Python 3.15, Flask 3.1.3, Werkzeug 3.1.9, шаблоны и статику.
- `android_entry.py` проверен локально на тех же исходниках: сервер поднимается на свободном loopback-порту, отдаются `/`, `/learn`, `/stats`, `/library`, CSS и manifest.
- Desktop-набор тестов: `198 passed`.

APK ещё не устанавливался и не запускался на физическом устройстве или эмуляторе: на машине сборки не было подключённого Android-устройства, а эмулятор x86_64 не запускается без аппаратной виртуализации. Поэтому поведение WebView, SAF-диалогов и жизненного цикла на Android пока не подтверждено. Это следующий обязательный шаг перед распространением APK.

## Доступ с телефона

Телефон и компьютер должны быть в одной Wi-Fi/локальной сети.

1. Запустите сервер с доступом по сети.

   PowerShell:

   ```powershell
   $env:NETPRACTICE_HOST = "0.0.0.0"
   python app.py
   ```

   cmd.exe:

   ```bat
   set NETPRACTICE_HOST=0.0.0.0
   python app.py
   ```

   Linux / macOS:

   ```bash
   NETPRACTICE_HOST=0.0.0.0 python app.py
   ```

   При использовании `run.bat` переменную нужно задать в том же окне до запуска.

2. Узнайте IP-адрес компьютера:

   - Windows: `ipconfig`, нужен **IPv4-адрес** активного адаптера;
   - Linux: `hostname -I` или `ip addr`;
   - macOS: `ipconfig getifaddr en0` (имя интерфейса может отличаться).

3. Откройте на телефоне:

   ```
   http://192.168.1.50:5000
   ```

   (подставьте свой адрес).

4. Если страница не открывается:
   - разрешите Python доступ к **частной сети** в брандмауэре Windows;
   - проверьте, что телефон не в «гостевой» сети с изоляцией клиентов;
   - убедитесь, что сервер запущен именно с `NETPRACTICE_HOST=0.0.0.0`;
   - попробуйте отключить мобильный интернет на телефоне, оставив Wi-Fi.

**Важно:** у приложения нет пароля и авторизации. Не открывайте его в интернет, не делайте проброс портов и не запускайте с `debug=True`. Режим `0.0.0.0` предназначен только для доверенной домашней/учебной сети.

### PWA на телефоне

На компьютере через `http://127.0.0.1:5000` Chrome/Edge считает страницу безопасной: манифест и service worker работают, приложение можно установить.

При открытии по `http://192.168.x.x:5000` браузеры обычно считают origin небезопасным. Сам тренажёр работает, но установка PWA и офлайн-кэш могут быть недоступны. Это ограничение браузера, а не приложения. Для полноценного PWA с телефона нужен HTTPS (например, локальный сертификат или reverse proxy).

## Библиотека и учебные пакеты

Раздел **«Библиотека»** отделён от встроенной программы. Системные модули 1–7 остаются в «Обучении», а пользовательские курсы устанавливаются из файлов `.nptpack` и запускаются через тот же движок занятий, XP и проверки ответов.

### Формат `.nptpack`

Это ZIP-архив только с данными:

```text
ipv4-basics.nptpack
├── manifest.json
├── questions.json
├── labs.json
└── assets/
    ├── subnetting-example.png
    └── topology-example.png
```

`manifest.json`:

```json
{
  "format": "nptpack",
  "format_version": 1,
  "id": "ipv4-basics",
  "title": "Основы IPv4 и подсетей",
  "description": "Изучение IPv4-адресации и подсетей",
  "author": "NetPractice Community",
  "module_version": "1.0.0",
  "language": "ru",
  "difficulty": "beginner",
  "category": "networking",
  "created_at": "2026-10-31",
  "min_app_version": "1.0.0"
}
```

- `id` не зависит от имени файла и проверяется по строгому шаблону.
- `format_version` версионирует формат пакета; версия выше поддерживаемой отклоняется.
- `module_version` и `min_app_version` — `X.Y.Z`.
- `difficulty`: `beginner`, `intermediate` или `advanced`.
- Системные идентификаторы (`system`, `netpractice`, `core`, `builtin`) зарезервированы.

`questions.json` — массив вопросов, совместимых с существующими типами: `input`, `multi`, `choice`, `scenario`, `troubleshoot`. Поддерживаются `answers`, `answer_kind`, `options`, `correct`, `fields`, `keywords`/`criteria`, `min_points`, `hints`, `explanation`, `sample`, `xp`, `difficulty` и `position`. Вопросы получают стабильный ID `npt:<pack_id>:<local_id>`.

`labs.json` — массив лабораторных работ с `id`, `title`, `description`, `goal`, `prerequisites`, `theory`, `steps`, `commands`, `expected`, `criteria`, `hints`, `explanation` и `assets`. Лаборатории помечаются как ручная проверка (`manual_check: true`); автоматической проверки лабораторий в этой версии нет. Команды и изображения только отображаются и никогда не выполняются.

### Импорт

1. Откройте **«Библиотека» → «Импортировать модуль»**.
2. Выберите `.nptpack`.
3. Приложение проверит ZIP, manifest, JSON, размеры, изображения и версии.
4. Покажется предпросмотр: автор, версия, сложность, категория, количество заданий, лабораторий и размер.
5. Нажмите «Установить» (для обновления — «Обновить»).

Предпросмотр **не меняет основную базу**: файл временно сохраняется в `instance/pending_packs/`, а запись выполняется только после подтверждения. При ошибке показывается понятное сообщение, а база остаётся прежней.

### Обновление и прогресс

- Повторный импорт того же `id` сравнивает версии.
- Одинаковая версия: сообщение «уже установлена», изменений нет.
- Новая версия: обновление; старые и новые задания сопоставляются по `local_id`/`qid`.
- Старая версия: предупреждение и обязательное подтверждение downgrade.
- Ответы, XP, серия и статистика не удаляются. Старое содержимое изменённых вопросов сохраняется в `custom_question_archive`, удалённые вопросы остаются в базе как неактивные.
- Обновление выполняется в транзакции `BEGIN IMMEDIATE`: при ошибке предыдущая версия остаётся рабочей.

### Удаление и системные модули

Удаление доступно только пользовательскому модулю. Модуль помечается как удалённый, его вопросы, лаборатории и изображения становятся неактивными, но история ответов и XP остаются. Повторная установка того же пакета восстанавливает модуль. Встроенные модули 1–7 удалить нельзя.

### Безопасность пакета

- архив не более **5 МБ**, распакованные данные — не более **20 МБ**, не более **60 файлов**;
- допускаются только `manifest.json`, `questions.json`, `labs.json` и `assets/*.png|jpg|jpeg`;
- изображения не более **2 МБ**, до **4096 px** по стороне и **16 Мп**;
- запрещены абсолютные пути, `..`, обратные слэши, символические ссылки, шифрованные записи, исполняемые файлы и неизвестные файлы;
- ZIP Slip и ZIP bomb блокируются до записи в базу;
- JSON проверяется по типам, длинам, обязательным полям и диапазонам;
- код из пакета не выполняется, изображения не распаковываются на диск, а хранятся как BLOB;
- SQL-запросы параметризованы; системные модули защищены.

### Создание и экспорт

Установленный пользовательский модуль можно скачать кнопкой **«Экспорт .nptpack»**: приложение собирает ZIP, прогоняет его через тот же валидатор и отдаёт файл.

Для подготовки пакета без редактора используйте `manifest.json`, `questions.json`, `labs.json` и описанную структуру. Демонстрационный пакет собирается скриптом:

```bash
python tools/build_demo_pack.py
```

Результат: `demo_packs/ipv4-basics.nptpack` — 15 заданий, 2 лабораторные работы, 2 изображения. Его можно сразу импортировать через интерфейс.

### Открытие модулей

- Модуль 1 открыт всегда.
- Следующий модуль открывается, когда вы **попробовали** не менее 60% заданий предыдущего модуля, но не меньше 3 заданий.
- Учитываются уникальные задания, а не количество попыток. Правильность для открытия не важна — важно попробовать.
- Например, для модуля 1 из 12 заданий нужно попробовать `ceil(12 × 0.6) = 8` заданий.

### Подбор заданий

- **Ежедневное занятие:** 8 заданий. Сначала новые вопросы текущего доступного модуля, затем ошибки из повторения и закрепление более ранних тем. Если новых вопросов не осталось, подбираются уже встречавшиеся.
- **Практика:** 6 заданий по выбранному модулю: сначала новые, затем ошибочные, затем остальные.
- **Повторение:** до 8 заданий из списка ошибок.
- Подбор для ежедневного занятия и практики воспроизводим для одной и той же даты и состояния прогресса, но не является «экзаменом»: цель — регулярная практика, а не случайная сложность.

Незавершённое занятие хранится в базе. Если закрыть вкладку, занятие продолжится с того же задания. Повторная отправка формы не начисляет XP дважды.

## Проверка ответов

### Короткие ответы, IP, маски, числа

- IP-адрес проверяется как адрес IPv4.
- Маска принимается в точечной записи (`255.255.255.0`) и в виде префикса (`/24`).
- CIDR и число узлов проверяются как целые значения.
- Для заданий типа «укажите шлюз» принимается любой корректный адрес узла внутри указанной подсети, а не только один заранее выбранный адрес.
- Регистр, лишние пробелы и знаки препинания в коротких текстовых ответах не мешают сравнению.

### Несколько полей

Каждое поле проверяется отдельно. В результате видно, какие поля совпали, а какие нет, и какой процент полей верен. Для зачёта задания нужны **все** поля; частичный результат показывается как обратная связь.

### Развёрнутые ответы

- Ответ сравнивается с ключевыми понятиями, а не с эталонным текстом дословно.
- Учитываются синонимы и разные формулировки, заданные в контенте.
- Показываются найденные и пропущенные пункты, образец ответа и объяснение.
- Автоматический зачёт требует минимального числа ключевых пунктов (по умолчанию — половина, но не меньше двух) и содержательного текста.
- Если ответ технически верен, но автопроверка его не зачла, можно нажать «Мой ответ верен по смыслу». XP за задание начисляется один раз; задание убирается из повторения.
- Кнопка «Понял ошибку» просто отмечает разбор; она не начисляет XP.

## XP, серия и дата

### XP

- У каждого задания свой XP (показан в интерфейсе).
- XP начисляется только за **первое верное** решение задания за всё время.
- Повторное решение, практика и повторение не начисляют XP за то же задание повторно.
- Завершение ежедневного занятия даёт **+15 XP** один раз в календарный день. Второе занятие в тот же день бонуса не даёт.
- XP за попытку хранится отдельно от самой попытки; импорт объединяет начисления без дублей.

### Серия

- Серия считается по уникальным календарным датам, в которые были ответы на задания.
- Если последняя активность была сегодня или вчера, текущая серия продолжается.
- Пропуск полного календарного дня обнуляет текущую серию.
- Максимальная серия хранится в истории и не уменьшается.
- Серия увеличивается не более одного раза за календарную дату, независимо от числа занятий.

### Дата и время

Используется **локальная дата сервера** (`date.today()`), а не дата браузера. Поэтому «сегодня» определяется компьютером, на котором запущен Flask. Если сервер и телефон находятся в разных часовых поясах, дата может отличаться от ожидаемой.

Для тестов дату можно зафиксировать через `app.config["TODAY_OVERRIDE"]`; в обычном запуске эта настройка не используется.

### Где хранится прогресс

По умолчанию:

```
instance/netpractice.db
```

Там же создаётся `instance/secret_key` — случайный ключ Flask. Папка `instance/` исключена из git через `.gitignore`.

Путь к базе можно изменить переменной `NETPRACTICE_DB`:

```powershell
$env:NETPRACTICE_DB = "D:\backups\netpractice.db"
python app.py
```

Каталог всех изменяемых данных можно перенести через `NETPRACTICE_DATA_DIR`. Тогда там будут созданы `netpractice.db`, `secret_key` и `pending_packs/`; desktop-значение по умолчанию остаётся `instance/`.

Для учебных пакетов добавлены таблицы `custom_modules`, `custom_questions`, `custom_labs`, `custom_assets` и `custom_question_archive`. Они создаются через `CREATE TABLE IF NOT EXISTS`; существующие таблицы уроков, попыток и XP не перестраиваются. Версия схемы обновляется до 2. Удаление пользовательского модуля не удаляет `attempts`, `question_awards`, `review_questions` и `daily_bonus`.

### Экспорт

Страница **«Данные» → «Экспорт прогресса»** скачивает JSON-файл `netpractice_backup.json`.

В файл входят:

- история ответов (`attempts`);
- начисления XP за задания (`question_awards`);
- список ошибок для повторения (`review_questions`);
- бонусы за ежедневные занятия (`daily_bonus`).

Незавершённое занятие в файл **не входит** — оно остаётся на текущем сервере.

Пример структуры:

```json
{
  "format": "netpractice-backup",
  "format_version": 1,
  "app": "NetPractice",
  "exported_at": "2026-10-29 12:00:00",
  "counts": {
    "attempts": 42,
    "question_awards": 30,
    "review_questions": 5,
    "daily_bonus": 6
  },
  "data": {
    "attempts": [],
    "question_awards": [],
    "review_questions": [],
    "daily_bonus": []
  }
}
```

### Импорт

Страница **«Данные» → «Импорт»**:

1. Выберите JSON-файл.
2. Выберите режим:
   - **Объединить** — добавить новую историю к текущей. Дубликаты ответов определяются по `uid`, начисления XP — по `question_id`. Повторно XP не начисляется.
   - **Заменить** — удалить текущий прогресс и загрузить данные из файла. Для этого нужно установить подтверждение.
3. Нажмите «Импортировать».

Ограничения и защита:

- максимум **2 МБ**;
- принимается только UTF-8 JSON;
- проверяются формат, версия, типы, диапазоны, даты и вложенные JSON-строки;
- файл более новой версии формата отклоняется с понятным сообщением;
- дубликаты внутри файла удаляются;
- код из файла никогда не выполняется — это только данные;
- при ошибке прогресс не меняется.

### Перенос на другой компьютер

1. На старом компьютере: **Данные → Экспорт**.
2. Перенесите JSON-файл любым способом (флешка, облако, мессенджер).
3. На новом компьютере установите приложение и запустите его.
4. **Данные → Импорт → Заменить** (или «Объединить», если там уже есть прогресс).
5. Для замены поставьте подтверждение.

Можно также скопировать сам файл `instance/netpractice.db` при остановленном сервере, но импорт JSON безопаснее и переносим между версиями.

### Сброс прогресса

1. Остановите сервер.
2. Сделайте экспорт или скопируйте `instance/netpractice.db`.
3. Удалите/переименуйте `instance/netpractice.db`.
4. Запустите приложение снова — база создастся пустой.

## Настройки запуска

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `NETPRACTICE_HOST` | `127.0.0.1` | Адрес прослушивания. `0.0.0.0` — доступ по локальной сети |
| `NETPRACTICE_PORT` | `5000` | Порт |
| `NETPRACTICE_DB` | `instance/netpractice.db` | Путь к файлу базы |
| `NETPRACTICE_DATA_DIR` | `instance/` | Каталог для базы, секретного ключа и временных импортов; в Android APK — `files/netpractice/` |

Пример с другим портом:

```powershell
$env:NETPRACTICE_PORT = "8080"
python app.py
```

Открывать: `http://127.0.0.1:8080`.

### Безопасность

- `debug=False` всегда; отладочный режим нельзя выставлять в сеть.
- Секретный ключ генерируется случайно и сохраняется в `instance/secret_key`.
- Ответы содержат ограничения CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`.
- Нет внешних скриптов, стилей и шрифтов.
- Импорт принимает только данные, не исполняет код.
- **Нет авторизации**: любой, кто имеет доступ к порту, видит и может менять прогресс. Это домашний однопользовательский тренажёр.

## Тесты

Установите зависимости и запустите:

```bash
python -m pytest -q
```

Фактический результат на момент сборки:

```

```

Это 198 тестов, включая проверки интерфейса, атомарности старта и учебных пакетов.

Поведенческие тесты интерфейса запускают `app.js` в установленном Chrome.
Если Chrome не найден, эти тесты пропускаются; остальные проверки выполняются.

Что покрыто:

- структура контента: 83 задания, уникальные ID, обязательные поля, допустимые правильные индексы, наличие ключевых пунктов у письменных заданий;
- 83 параметризованные проверки эталонных ответов;
- IP, маски в двух формах, CIDR, число узлов, адрес сети, broadcast, пересечения подсетей;
- частичные ответы, регистр/пробелы/ё, пустые ответы, ключевые слова и самопроверка;
- начисление XP только один раз, бонус за день, серия и её разрыв, повторение ошибок;
- сохранение и продолжение незавершённого занятия после перезапуска;
- объединение и замена резервной копии, дедупликация, неверные версии и повреждённый JSON;
- основные маршруты приложения, PWA-эндпоинты, страница 404;
- `.nptpack`: импорт, предпросмотр без изменений БД, обновление, downgrade, удаление с архивом истории, экспорт и повторный импорт;
- безопасность пакетов: ZIP Slip, исполняемые файлы, неизвестные файлы, повреждённый ZIP, неверные версии и типы, большие архивы, неверные изображения;
- атомарность обновления: ошибка в середине транзакции оставляет предыдущую версию;
- встроенные модули защищены от удаления и перезаписи.

Тесты используют временные базы и не трогают ваш реальный прогресс.

## Ограничения

- **Один пользователь.** Нет аккаунтов, ролей и синхронизации между устройствами. Телефон и компьютер работают с одной базой на сервере.
- **Локальная дата сервера.** Смена часового пояса или перевод часов может повлиять на «сегодня», серию и бонус.
- **PWA на телефоне по HTTP.** Установка и service worker требуют безопасного origin (`localhost` или HTTPS). В Android APK PWA-установка не используется: интерфейс открывается во встроенном WebView.
- **Проверка текста по ключевым словам.** Синонимы ограничены контентом; для спорных случаев есть самозачёт.
- **Flask development server.** Подходит для локального и домашнего использования, но не для публичного интернета.
- **Нет шифрования базы.** Файл SQLite и резервные копии читаются тем, у кого есть доступ к файлам.
- **Импорт только своего формата.** Формат `netpractice-backup` версии 1; чужие JSON не принимаются.
- **Статичный контент.** Задания не генерируются ИИ и не адаптируются под скорость обучения; подбор лишь учитывает новые темы и ошибки.
- **Пользовательские модули пока не входят в ежедневное занятие.** Они запускаются из «Библиотеки» через общий lesson-движок; встроенная программа 1–7 остаётся отдельной.
- **Лабораторные работы проверяются вручную.** Автоматического выполнения и проверки лабораторий нет; команды и изображения только отображаются.
- **Нет визуального редактора пакетов.** Пакет собирается из JSON/ZIP или скриптом; экспорт доступен для установленных пользовательских модулей.
- **Изображения только PNG/JPEG.** SVG и другие форматы не принимаются из соображений безопасности.
- **Android APK пока debug.** Он подписан debug-ключом и предназначен для локальной установки; для публикации нужен отдельный release-keystore. Запуск на реальном Android-устройстве ещё не проверен.
- **JSON-резервная копия прогресса не содержит содержимого установленных пакетов.** Для переноса курсов экспортируйте их отдельными `.nptpack`; история ответов при этом сохранится, но без установленного пакета задания останутся архивными.

## Идеи развития

- интервальное повторение (например, 1–3–7 дней) вместо простого списка ошибок;
- адаптивная сложность и больше лабораторных работ;
- отдельные профили для нескольких пользователей;
- экспорт статистики в CSV;
- напоминания о резервной копии и автосохранение;
- локальный HTTPS для установки PWA на телефоне;
- QR-код с адресом сервера на странице «Данные»;
- тёмная/светлая темы и настройка размера шрифта;
- полноценный офлайн-режим с IndexedDB (сейчас офлайн доступна только оболочка).

## Частые проблемы

**`python` не найден.** Установите Python 3.11+ и включите «Add Python to PATH». На Windows можно использовать `py -3`.

**`run.sh: Permission denied`.** Выполните `chmod +x run.sh`.

**Порт 5000 занят.** Задайте другой порт: `NETPRACTICE_PORT=8080`.

**Телефон не подключается.** Проверьте `NETPRACTICE_HOST=0.0.0.0`, IP-адрес, брандмауэр и то, что устройства в одной сети. Гостевые Wi-Fi часто изолируют клиентов.

**Первый запуск без интернета не работает.** Нужно один раз установить Flask и pytest. После этого приложение работает офлайн.

**Не устанавливается как приложение на телефоне.** Ожидаемо при открытии по `http://IP:5000`: нужен HTTPS или `localhost`.

**Странная дата или серия.** Проверьте дату и часовой пояс компьютера, на котором запущен сервер.
